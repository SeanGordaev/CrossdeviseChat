# CrossdeviseChat

[English](README.md) | [Русский](README_RU.md)

**CrossdeviseChat** — это лёгкое самохостящееся приложение для общения между устройствами, подключёнными к одной локальной сети (LAN).

Один компьютер — либо отдельная машина в локальной сети — запускает **сервер** из папки `Backend`. Остальные компьютеры запускают **клиент** из папки `Frontend` и подключаются к серверу по его локальному IP-адресу и порту.

Цель проекта — создать простой локальный чат, который не зависит от внешних сервисов обмена сообщениями или облачной инфраструктуры.

> 🚧 **Проект в разработке:** CrossdeviseChat всё ещё развивается. Протокол, интерфейс и функциональность могут изменяться.

---

## Как это работает

CrossdeviseChat использует **клиент-серверную архитектуру**:

```text
                 Локальная сеть
                       │
          ┌────────────┴────────────┐
          │                         │
     ┌────▼─────┐             ┌────▼─────┐
     │ Клиент A │             │ Клиент B │
     └────┬─────┘             └────┬─────┘
          │                         │
          └──────────┬──────────────┘
                     │
               TCP-соединения
                     │
               ┌─────▼─────┐
               │   Сервер  │
               │   / Хост  │
               └─────┬─────┘
                     │
               messages.txt
```

Сервер:

- ожидает входящие TCP-подключения;
- хранит список подключённых клиентов;
- создаёт отдельный поток для каждого подключённого клиента;
- получает сообщения от клиентов;
- рассылает полученные сообщения всем подключённым клиентам;
- сохраняет сообщения в `Backend/messages.txt`.

Хостом может быть:

- один из компьютеров, участвующих в чате;
- отдельный компьютер;
- небольшой локальный сервер, подключённый к LAN.

Для общения внутри локальной сети подключение к Интернету не требуется.

## Текущие возможности

Текущая версия включает:

- клиент-серверное общение через TCP;
- несколько одновременно подключённых клиентов;
- постоянные TCP-соединения;
- рассылку сообщений в реальном времени;
- общий чат для подключённых клиентов;
- простой графический интерфейс на Tkinter;
- отправку сообщений кнопкой **Send** или клавишей **Enter**;
- серверное хранение сообщений в `messages.txt`;
- отдельные конфигурационные файлы сервера и клиента;
- протокол сообщений с 2-байтовым полем длины;
- многопоточную обработку клиентов на сервере.

## Структура проекта

Все **серверные файлы** находятся в `Backend/`.

Все **клиентские файлы** находятся в `Frontend/`.

```text
CrossdeviseChat/
│
├── Backend/
│   ├── config.json
│   ├── messages.txt
│   ├── server.py
│   └── start_servet.bat
│
├── Frontend/
│   ├── chat_client.py
│   ├── chat_client_gui.py
│   ├── config.json
│   └── start_client.bat
│
├── README.md
└── README_RU.md
```

> **Примечание:** текущий файл запуска сервера называется `start_servet.bat`. Для единообразия лучше переименовать его в `start_server.bat`.

### Backend

Папка `Backend` содержит всё необходимое для запуска сервера.

- `server.py` — сетевая логика сервера;
- `config.json` — локальный IP-адрес и порт сервера;
- `messages.txt` — простое постоянное хранилище сообщений;
- `start_servet.bat` — Windows-файл для быстрого запуска сервера.

### Frontend

Папка `Frontend` содержит всё необходимое для запуска клиента.

- `chat_client.py` — сетевая логика клиента;
- `chat_client_gui.py` — графический интерфейс на Tkinter;
- `config.json` — адрес сервера, к которому должен подключиться клиент;
- `start_client.bat` — Windows-файл для быстрого запуска клиента.

## Протокол сообщений

CrossdeviseChat использует TCP-сокеты.

TCP является **потоком байтов**, поэтому один вызов `recv()` не обязан содержать ровно одно полное сообщение. Чтобы решить эту проблему, CrossdeviseChat добавляет перед каждым сообщением его размер:

```text
┌──────────────────┬────────────────────────────┐
│ Размер сообщения │ Данные сообщения           │
│ 2 байта           │ N байт                     │
└──────────────────┴────────────────────────────┘
```

Первые **2 байта** в формате big-endian содержат размер сообщения.

Получатель:

1. читает ровно 2 байта;
2. преобразует их в длину сообщения;
3. читает указанное количество байт;
4. декодирует полученные данные как текст.

При 2-байтовом беззнаковом поле длины одно сообщение может содержать до **65 535 байт**.

## Требования

- Python 3
- Tkinter
- поддержка TCP/IP
- устройства в одной локальной сети
- правила firewall/сети, разрешающие выбранный TCP-порт

Сервер и клиенты должны иметь возможность связываться друг с другом через локальную сеть.

## Начало работы

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/SeanGordaev/CrossdeviseChat.git
cd CrossdeviseChat
```

---

### 2. Установите Python и необходимые библиотеки

CrossdeviseChat в текущем виде использует только модули из стандартной библиотеки Python:

- `socket`
- `json`
- `threading`
- `pathlib`
- `tkinter`

Поэтому **устанавливать дополнительные пакеты через `pip` сейчас не требуется**.

В Windows Python можно установить прямо из командной строки с помощью WinGet:

```powershell
winget install --id Python.Python.3.14 --exact
```

После завершения установки закройте и снова откройте терминал, затем проверьте Python:

```powershell
python --version
```

Также можно проверить работу Tkinter:

```powershell
python -m tkinter
```

Если Tkinter установлен правильно, откроется небольшое тестовое окно.

Если Python уже установлен и обе команды работают, этот шаг можно пропустить.

---

### 3. Настройте сервер

Откройте:

```text
Backend/config.json
```

Пример:

```json
{
    "your-ip-local": "192.168.1.100",
    "your-port-local": "5050"
}
```

Этот файл сообщает серверу **кто он в локальной сети**:

```text
Backend/config.json
        │
        └── "Кто я?"
            │
            ├── Локальный IP сервера
            └── Локальный порт сервера
```

`your-ip-local` — локальный IP-адрес компьютера, который будет хостом чата.

`your-port-local` — TCP-порт, на котором сервер будет ожидать подключения клиентов.

Например:

```text
192.168.1.100:5050
```

---

### 4. Настройте клиент

Откройте:

```text
Frontend/config.json
```

Пример:

```json
{
    "connect-to-ip-local": "192.168.1.100",
    "connect-to-port-local": "5050"
}
```

Этот файл сообщает клиенту **к кому он должен подключаться**:

```text
Frontend/config.json
        │
        └── "К кому подключаться?"
            │
            ├── IP сервера
            └── Порт сервера
```

Значения клиента обычно должны совпадать с IP-адресом и портом, указанными в `Backend/config.json` на серверном компьютере.

Если к одному чату хотят подключиться несколько компьютеров, все клиенты должны указывать один и тот же сервер.

## Запуск сервера

### Windows — быстрый запуск

Откройте папку `Backend` и запустите:

```text
start_servet.bat
```

BAT-файл автоматически переходит в папку `Backend` и запускает:

```bash
python server.py
```

### Ручной запуск

Из корня проекта:

```bash
cd Backend
python server.py
```

Сервер должен оставаться запущенным, пока клиенты используют чат.

---

## Запуск клиента

Перед запуском убедитесь, что в `Frontend/config.json` указаны правильные IP-адрес и порт сервера.

### Windows — быстрый запуск

Откройте папку `Frontend` и запустите:

```text
start_client.bat
```

BAT-файл автоматически переходит в папку `Frontend` и запускает GUI:

```bash
python chat_client_gui.py
```

### Ручной запуск

Из корня проекта:

```bash
cd Frontend
python chat_client_gui.py
```

Повторите это на каждом компьютере, который должен подключиться к чату.

## Пример сети

```text
Роутер
192.168.1.1
     │
     ├── Сервер / Хост
     │   192.168.1.100:5050
     │
     ├── Клиент A
     │   192.168.1.101
     │
     ├── Клиент B
     │   192.168.1.102
     │
     └── Клиент C
         192.168.1.103
```

Все клиенты подключаются к:

```text
192.168.1.100:5050
```

Клиентам не нужно устанавливать прямое соединение друг с другом:

```text
Клиент A ──┐
           │
Клиент B ──┼──► Сервер ──► Рассылка подключённым клиентам
           │
Клиент C ──┘
```

## Многопоточность

Для каждого подключённого клиента сервер создаёт отдельный поток.

Общий список клиентов защищён блокировкой во время добавления, удаления и копирования списка для рассылки.

Благодаря этому несколько клиентов могут одновременно оставаться подключёнными к одному серверу.

---

## Хранение сообщений

Каждое обычное сообщение, полученное сервером, добавляется в:

```text
Backend/messages.txt
```

Это обеспечивает базовое постоянное хранение сообщений на стороне сервера.

Сейчас сохранённые сообщения **не отправляются автоматически новым подключившимся клиентам**. Клиент видит сообщения, которые были разосланы сервером во время его подключения.

## Текущие ограничения

CrossdeviseChat всё ещё является экспериментальным проектом.

В текущей версии пока нет:

- имён пользователей;
- временных меток;
- автоматической синхронизации истории чата;
- автоматического поиска сервера в локальной сети;
- автоматического переподключения;
- аутентификации;
- шифрования соединения;
- передачи файлов;
- удобного экрана настройки;
- полностью реализованного корректного отключения клиента через GUI.

Сервер также распознаёт специальное сообщение:

```text
EXIT_USER_NOW
```

как команду отключения, однако текущий GUI пока не предоставляет полноценную пользовательскую систему отключения на основе этой команды.

## Безопасность

CrossdeviseChat в текущем виде предназначен для использования внутри **доверенных локальных сетей**.

Текущий протокол не предоставляет аутентификацию или шифрование. Поэтому приложение **не следует напрямую открывать в публичный Интернет**.

Возможные будущие улучшения:

- аутентификация клиентов;
- шифрование соединений;
- система прав;
- проверка сообщений;
- ограничения подключений и защита от злоупотреблений.

## Мотивация проекта

Большинство современных приложений для общения зависят от внешних серверов и подключения к Интернету.

CrossdeviseChat исследует другой подход:

> **Если устройства уже подключены к одной локальной сети, они должны иметь возможность общаться через инфраструктуру, которую контролируют сами пользователи.**

Проект также позволяет изучать:

- TCP-сокеты;
- клиент-серверную архитектуру;
- разделение сообщений в TCP-потоке;
- многопоточность;
- одновременную работу с несколькими соединениями;
- локальную IP-адресацию;
- сетевые протоколы;
- серверную рассылку сообщений;
- взаимодействие GUI и сетевого кода;
- жизненный цикл сетевого соединения.
